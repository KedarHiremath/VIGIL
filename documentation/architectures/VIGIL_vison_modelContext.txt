### How we expect VIGIL to work

1. Investigator submits footage. The API receives the investigation request and passes it to application services.
2. Media is ingested and indexed. VIGIL validates the input, extracts relevant metadata, prepares media for analysis, and stores the media or durable references to it.
3. The planner creates an investigation plan. Based on the objective and available capabilities, it proposes the analysis tasks required. The plan may include visual analysis, audio analysis, temporal correlation, and evidence verification.
4. The orchestrator manages execution. It coordinates agents, dependencies, execution state, and checkpoints. It determines what can run, handles results, and supports controlled replanning.
5. Visual and audio agents analyze the footage. They use tools and model adapters to identify potentially relevant objects, actions, sounds, speech, or other signals. Each output should retain its timestamp or time interval and its source reference.
6. Temporal and correlation analysis combines findings. It relates observations from different times and modalities to identify sequences, overlaps, and potentially related events.
7. Evidence verification assesses findings. It checks supporting evidence, uncertainty, conflicts, and whether a conclusion is sufficiently supported. Findings that need further work can return to the orchestrator.
8. The report writer produces the investigation report. It combines validated findings into a detailed, structured report with timelines, evidence references, and relevant video or audio clips.
9. Human review and audit complete the process. Investigators can review the report, and report versions and review decisions are recorded.

The diagram represents the intended architecture, not necessarily the current implementation. The order of execution can vary: independent audio and visual tasks may run in parallel, while dependent tasks must wait for the information they need.

## Essential VIGIL requirements

These requirements should guide every future design decision.

- Timestamp everything relevant. Preserve the media's original time information, use video-relative timestamps for exact positions within footage, and record absolute timestamps where they can be reliably established. Distinguish a point in time from an interval.
- Keep evidence traceable. Every finding should link to the source footage, relevant time interval, and any derived artifact or analysis that supports it.
- Provide incident clips. The system should identify relevant intervals and produce or reference playable clips with start and end timestamps. Clips should be derived from the original media and retain enough context for investigators to review them.
- Analyze audio and video together. A sound, spoken phrase, visible action, and associated event may provide complementary evidence. The system should correlate them without assuming that temporal coincidence proves causation.
- Distinguish detection from conclusion. A model's detection is an observation, not automatically a verified incident. Reports must represent uncertainty and conflicting evidence honestly.
- Generate detailed, evidence-grounded reports. Reports should contain an executive summary, event timeline, relevant observations, evidence clips, supporting sources, verification status, uncertainty, and limitations as appropriate.
- Support long-running investigations. Execution state and checkpoints should make progress recoverable, with a clear record of completed, failed, and outstanding tasks.
- Keep components modular. Model providers, analysis tools, agents, the planner, scheduler, repositories, and reporting should be replaceable without redesigning the entire system.

## Instructions for models planning future implementation

A model working on VIGIL should first inspect the latest repository, existing tests, documentation, and architecture diagram. It should identify what is implemented, partially implemented, missing, or inconsistent with the intended workflow before proposing code changes.

It should then:

1. Map existing files and interfaces to the architecture above.
2. Identify the next smallest meaningful implementation stage and its prerequisites.
3. Define the required contracts and responsibilities before implementing dependent components.
4. Preserve existing working behavior and avoid duplicating capabilities already present.
5. Implement one coherent stage at a time, with tests and documentation.
6. Run the appropriate project checks and report actual results.
7. Explain the next stage only after establishing that the current stage meets its exit criteria.

The model must not assume that all components in the diagram already exist, nor should it build every agent at once simply because those agents appear in the target architecture.

The central vision: VIGIL is an evidence-oriented, multimodal video investigation system. It takes footage and an investigation objective, analyzes audio and visual information, correlates events over time, verifies findings, and produces detailed reports with timestamped, reviewable clips from the original footage. Its agentic architecture should make this process adaptive and extensible, while its contracts, evidence traceability, and execution controls keep it reliable and auditable.
